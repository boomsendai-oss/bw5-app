# 体験予約 担当インストラクター周知の自動化（設計）

作成: 2026-07-18 / WS T / TARO承認済み（口頭・2026-07-18）

## 背景・課題

体験レッスンの予約は Lstep（体験予約カレンダー）に入る。TARO/KEIKO は担当インストラクターへ
「今日このレッスンに体験の方が来ます」と**事前周知**している。現状の手作業:

1. Lstep 管理画面を開く
2. 予約詳細を探す
3. その画面をスクショ
4. 担当インストラクターへ個人LINEで画像を送信

この「Lstep を開く→探す→スクショ」が煩わしい。**送信自体は今まで通り TARO/KEIKO が個人LINEで行う**
（先生にアプリを見る習慣は定着しないため。TARO判断 2026-07-18）。

### 技術的制約（確定事項）
- **個人LINE（TARO/KEIKO 個人アカウント）からの自動送信は不可**（外部APIが存在しない）
- BOOM公式LINEは Lstep 運用でありプッシュ自動化の前提が重い → v1では採用しない

## 採用アプローチ

**アプリに「体験予約」ページを新設し、担当ごとに整形済みテキストをワンタップでコピー。
TARO/KEIKO は LINE を開いて貼り付けて送信するだけ。**

- スクショ・Lstep操作が消え、送信はコピー＆ペーストで完結
- 個人LINE / 公式LINE の制約に一切依存しない（最も手堅い）

## スコープ

### 1. 取込の下ごしらえ（enabler）
現状 `trial-import` は Lstep 体験CSVの一部列を破棄している。周知メッセージに必要な項目を保存する。

- `trial_records` に列追加:
  - `course_type` TEXT … CSV「コース」（体験レッスン / 見学）
  - `dance_experience` TEXT … CSV「ダンス経験」
  - `referral_source` TEXT … CSV「何でBOOMを知りましたか？」
- `trial-import` のマッピングを上記3列に拡張（既存の UPSERT に COALESCE で追記）
- あわせて CSV「来店/来場」列（済み/なし）を読み、`済み` を `status='来店確認済'` に反映する。
  （現状「ステータス」列は 予約済み/キャンセル済み の2値しか無く、来店実績が全期間0件＝
  体験→入会ファネルKPIが機能していない。同じ取込経路で直せるため同時に修正）
- **電話番号は保存しない**（周知に不要＋個人情報最小化。CLAUDE.md 規約8）

### 2. 表示・コピー機能
新ページ `/staff/trials`（サーバーコンポーネントで `trial_records` を読み、コピーはクライアント）

- 今日を先頭に、**日付 × レッスン枠（＝担当インストラクター）** で体験者をグルーピング
- 明日以降の予約も見られる（事前周知のため。キャンセルは除外、または淡色表示）
- 各グループ（＝1レッスン）に「コピー」ボタン。その枠の全員が1メッセージにまとまる
  （先生1人に1回送るだけ）
- ページ上部に「最終更新: HH:MM」（データ鮮度バッジ）

#### 氏名の表示
- **ひらがなのフルネーム**。CSV「お名前(カナ)」（カタカナ・全件入力あり）をひらがなに変換して表示。
  姓名の区切りは元データに無いため連結表示（例: ヤマダハナ → やまだはな）。

#### コピーされるテキスト（例・ダミー）
```
【本日の体験】7/18(金) 18:30〜
AOI 七ヶ浜 入門
──────────
・はなちゃん（8歳）／体験／ダンス未経験／きっかけ: Instagram
・そうたくん（10歳）／体験／経験あり／きっかけ: 友だち紹介
```
- 各行 = 1名: `ひらがなフルネーム（年齢）／コース／経験／きっかけ`
- 年齢・経験・きっかけが空欄なら省略（欠損に強く）

## データフロー
```
Lstep体験CSV ──(既存 daily_sync 6h毎)──▶ trial-import API ──▶ trial_records(DB)
                                                                    │
                                                       /staff/trials が読取・整形
                                                                    │
                                          TARO/KEIKO がコピー → LINE貼付 → 送信
```
- Lstep・フォームは変更しない。既存同期にそのまま乗る
- 鮮度は既存同期に依存（`daily_sync` は Mac依存で稀に失敗。ページに最終更新時刻を出して可視化）

## 非対象（YAGNI）
- 公式LINE / Messaging API プッシュ
- 先生ごとのログイン・個別ページ
- レッスン→インストラクター→連絡先のマッピングテーブル（枠名に担当名が入るため不要。送信先は人が選ぶ）
- 電話番号の保存・表示
