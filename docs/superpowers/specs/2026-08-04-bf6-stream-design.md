## 2. アーキテクチャ(推奨: Cloudflare Stream Live)

```
[スマホ(Larix Broadcaster・無料)]
   │ RTMPS push(会場回線 or 5Gテザリング)
   ▼
[Cloudflare Stream Live Input]  ← 自動録画(アーカイブ見逃し配信も同じ仕組みで可)
   │ HLS(署名付きURL・短寿命JWT)
   ▼
[/bf6/stream/watch 視聴ページ]  ← ログインキー認証+ハートビートで同時1接続制御
```

- **なぜCloudflare Stream**: 従量課金が安い(配信$1/1000分視聴・保存$5/1000分)。100人×3.5h≒
  21,000分≒$21+月額$5程度。**署名付き再生URL(JWT・有効期限つき)を公式サポート**=URL単体を
  転送されても数分で死ぬ。BOOMはCloudflareアカウント保有済み(boom-hpがPages)=Stream有効化のみ
- 代替: Mux(ほぼ同等・やや高い)。YouTube限定公開は流出対策不可のため不採用(7/28調査どおり)
- 遅延: 通常HLSで10〜20秒。双方向性がないイベント配信では実害なし(7/28調査どおり)

## 3. データ設計(bf_既存テーブル+2)

- 購入は既存の `bf_orders`/`bf_order_items`(item_type='stream'・予約済み)をそのまま使う
- `bf_stream_keys` — 視聴キー。order_id / key(UNIQUE・推測不可) / email / status(active/revoked) / created_at
  - Webhookでpaid確定した瞬間に発行しメール送信(エントリー完了メールと同じ流儀)
- `bf_stream_sessions` — 同時1接続制御。key_id / session_id / last_seen_at / user_agent(端末表示用)
- 設定は `bf_settings` に追加キー(stream_price / stream_open / cf_live_input_uid 等)

## 4. 同時1接続の制御(ハートビート方式)

1. 視聴ページでメール+ログインキーを入力
2. サーバ: キー有効性を確認 → `bf_stream_sessions` を見て**60秒以内に生存している別セッションが
   あれば拒否**(「他の端末で視聴中です」)。なければ新session_id発行で乗っ取り登録
3. 視聴中はプレイヤーが**20秒ごとにハートビート**(session_id付き)→ last_seen更新+**新しい署名付き
   再生トークン(有効5分)を受取り**
4. タブを閉じる/切断→ハートビートが止まる→60秒で枠が空き、他端末からログイン可能に
5. 再生URLは5分で失効するため、URLだけ共有しても他人は見続けられない

- 「ログアウトボタン」も置くが、押し忘れても60秒で自動解放されるので運用事故にならない
- レート制限は既存 `checkRateLimit` 流用(キー総当たり対策)

## 5. 画面構成

```
/bf6/stream          販売LP(料金・視聴方法・注意事項=通信環境起因は返金不可)
/bf6/stream/watch    視聴ページ(メール+キー入力→プレイヤー。Phase Cでいいね/コメント追加)
/staff/bf6/stream    スタッフ: 配信設定(Live Input情報)・キー一覧・強制切断・売上
```

購入導線: `/bf6/stream` → Stripe Checkout(既存基盤・item_type='stream') → Webhook paid →
キー発行メール。エントリーフォームへの同時購入組込みは**やらない**(エントリー者は現地に居るので
配信不要。別導線の方が説明もシンプル)←要TARO確認

## 7. 技術以外の残リスク(7/28調査から変わらず・アプリでは解決しないもの)

1. **カメラを回す人**(TAROはMC)→ 担当者アサイン
2. **会場の上り回線**(5Mbps以上欲しい)→ SSMのWi-Fi実測 or 5Gテザリング。リハで確定
3. **音声**: スマホマイクだと会場音がこもる。DJミキサーからのライン取り(スマホ用オーディオIF)を推奨
4. 撮影スマホの給電・発熱(3.5時間連続)→ 電源+スタンド
