# インスタストーリーズ自動投稿 タイミング設計 (2026-07-16)

## 背景

「毎日12:00に曜日別レッスン告知を自動投稿」で基盤を組んでいたが、**12:00固定は運用方針として未確定**だった（実装済み"基盤"の暫定値をそのまま確定扱いしていた誤り）。TAROから設計し直しの指摘。

## 目的（TARO整理・2026-07-16）

1. **IGを"生きてる/フレッシュ"に保つ**のが第一。更新が止まっている状況を打開する。
2. **設置面（見られる面）を増やす**ための毎日1回投稿。直接集客は「微妙」でよい（面の確保が主目的）。
3. **運営リソースほぼゼロ**で回すのが必須条件 → 決まった告知は自動化する。

## 決定（v1）

- **投稿時刻 = 毎朝 8:00 JST**（GH Actions cron `0 23 * * *` UTC）。朝の活動の山を取りつつ「今日のレッスン」を一日中正確に保つ。
- **内容 = 曜日別「今日のレッスン」告知動画**（事前作成の定型物）。
- **投稿対象日 = `public/stories/{曜日}.mp4` がある曜日のみ**。火曜（レッスン無し）や動画未生成日は動画が無い＝自動スキップ。動画の有無をゲートにするので専用のレッスン判定ロジックは持たない（YAGNI）。
- **自動投稿（毎回承認不要）**。事前にTARO確認済みの定型動画で低リスクなため。
- **冪等**（同日 `status='posted'` があれば再投稿しない）。手動テストと定時cronの重複を防ぐ。

## 素材選択の設計（同日追記・TARO承認済み）

**芯**: 「今日の素材があれば出す・なければ出さない・素材を作るのはTARO(別セッション)・Claudeは選んで出すだけ」。

背景: 土日はラインナップが週によって変わりうる（平日はほぼ固定）。当初Claudeが「データから素材をその場で自動生成」を提案したが、TAROの方針で**自動生成は一切しない**。間違った素材や低品質な生成物を出すより、**投稿しない方がマシ**（急ぎで手動作成→手動投稿する逃げ道もある）。

**毎朝8:00の優先チェーン**:

1. **日付指定オーバーライド** `public/stories/{YYYY-MM-DD}.mp4` — 土日の変動・講師交代・特別な日用。最優先。
2. **曜日デフォルト** `public/stories/{曜日}.mp4` (sun〜sat) — 毎週固定ラインナップの日用。
3. **(v2で追加予定)** 承認済み埋め草キュー — レッスンが無い日用。
4. **どれも無ければ投稿しない（ブレーキ・fail-closed）**。

- 素材の作り置きは別セッション（memory `project_daily_lesson_story`）が担当。上記の命名で `public/stories/` に置けば自動で拾われる。
- 冪等ガード（1日1本）は全チェーンに共通で効く。

## v2「埋め草」設計（承認済み・実装は別途）

目的: レッスンが無い日（火曜等）もIGを生きた状態に保つ。ネタ元 = ①今後のイベント告知 ②体験・入会誘導 ③過去の発表会/イベントのハイライト ④進行中プロジェクトの進捗。

- **事前承認キュー方式**: Claudeが候補をまとめて作成（既存素材の再利用優先）→ TAROがまとめて承認 → 承認済みキューに滞留 → 空き日に自動で1本消化。**日々のTAROの手間ゼロ**。
- 新テーブル `story_queue`: media_path / kind(event|promo|highlight|progress) / valid_from/valid_until(期限付き用・NULL=エバーグリーン) / status(pending|approved|posted|rejected|expired) / last_posted_at / times_posted。
- 選択順: 期限付きでwindow内のものを締切近い順 → 無ければエバーグリーンを last_posted_at 古い順にローテーション。
- 承認画面は `/staff/instagram` を拡張（プレビュー付き承認/却下・キュー残数・残少警告）。
- キューが空なら投稿しない（ブレーキ同様）。

## 実装

- `.github/workflows/instagram-story-cron.yml`: cron `0 3 * * *` → `0 23 * * *`。
- コメント/画面文言(`/staff/instagram` description)を8:00に更新。
- cron素材選択: 日付指定 `{YYYY-MM-DD}.mp4` → 曜日 `{曜日}.mp4` → スキップ、の優先チェーン実装。
- 既存コード（曜日判定 `weekdayJst`・冪等ガード）はそのまま流用。
- v2（story_queue＋承認画面＋キュー消化）は本設計に基づき別途実装。
