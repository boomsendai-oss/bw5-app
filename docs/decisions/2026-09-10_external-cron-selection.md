# 自動投稿の発火役を外部cronへ: 基盤の選定と移行

- 日付: 2026-09-10
- 決定: **Cloudflare Workers の Cron Triggers** を一次の発火役にする（2026-08-03に導入済みの `workers/boom-cron` を正式な一次に格上げし、時刻表の漏れを修正）
- 背景の実害: 9/9 の18:30枠が21:00に投稿され watchdog が要対応メールを送信。9/10の朝ストーリーが深夜01:24に公開

## なぜ発火役を移すのか

GitHub Actions の `schedule` は実測で大幅に遅れる（bw5-app は定期ワークフローが19本あり後回しにされる）。

| 枠(JST) | 実際の発火 | 遅延 |
|---|---|---|
| 朝 8:00 | 9:22〜10:22 | +1.5〜2h |
| 12:00 | 17:00頃 | +5h |
| 18:30 | 22:50 | +4h20m |
| 21:00 | 翌 1:23 | +4h20m |

遅延は「間に合わない」だけでなく**積極的に害になる**。21:00枠ぶんは JST の日付をまたいで翌01:2x に発火し、`post-story` の朝の素材（曜日デフォルト）には時刻ガードが無い（その日まだ投稿していなければ出す）ため、**翌日の朝ストーリーが深夜1時台に公開された**。

## 候補の比較

| 候補 | 分精度 | 費用 | 判定 |
|---|---|---|---|
| **Cloudflare Workers Cron Triggers** | ◎ 分単位 | 無料（10万リクエスト/日・毎分起動=1,440/日） | **採用** |
| Vercel Cron (Hobby) | ✕ 分精度の保証なし | 無料だが本数上限 | 不採用 |
| cron-job.org など外部SaaS | ◎ | 無料枠あり | 不採用（アカウントが増える） |
| GitHub Actions `schedule` | ✕ 実測+1.5〜5h | 無料 | 一次から降格（予備として一時維持） |

**採用理由**: ①分単位で正確 ②無料枠に余裕をもって収まる ③BOOMは既に Cloudflare を使っている（Pages でHP、R2でリール素材）ので管理画面・アカウント・請求が増えない ④Worker のコードに時刻表を持てるので**変更が1箇所で済む**（cronトリガーを時刻ごとに並べる必要がない）。

## 実装

- `workers/boom-cron/index.js` の `JOBS` 配列が時刻表の正本。毎分起動し、JSTの `HH:MM` が一致した仕事だけ叩く
- ストーリー: 08:00 / 12:00 / 12:30 / 18:30 / 21:00（各 +3分 の予備発火を1本）
- リール: 19:00 / 20:00（各 +12分 の予備）
- 見張り役 `story-watchdog`: 09:10 / 19:40（GETのみなので `method` を指定）。`vercel.json` のcron枠から移設し、Hobbyの2枠を解放した
- 鍵は `CRON_SECRET_CF`（`wrangler secret` のみ・Gitには置かない）。`CRON_SECRET` は Vercel が `[SENSITIVE]` でマスクして値が読めないため、鍵を回さず第2の鍵を増やす方式（`post-story` / `post-reel` と同じ既存パターン。今回 `story-watchdog` も同じ扱いにした）
- 手動発火は `?run=<label>` ＋ `x-cron-secret` ヘッダ。**鍵なしは401**（workers.dev のURLは推測できるため、無認証だと第三者が投稿を叩ける）

## 見落としていた2点（9/9事故の正体）

1. **18:30枠が時刻表に無かった**。2026-08-21にアプリ側（`story_day_slot`）へ追加された枠を Worker に足し忘れていた。そのため次の21:00枠まで待たされた
2. **07:59 着火が 08:00 の枠を取りこぼす**。`post-story` は「`slot_time <= 現在のJST時刻` でまだ出していない枠」を出す期限方式なので、前倒し着火は枠を「まだ予定時刻前」と判定する。定刻に撃つ必要がある

→ **アプリ側で枠の時刻を増やしたら、Worker の `JOBS` にも必ず足す**。

## GitHub Actions の扱い

- 21:00枠ぶん（UTC 12:03 / 12:23）は**害があるため即削除**
- 残り（朝・正午・夕方）は遅れても同じJST日のうちに収まり、二度打ちは冪等に吸収されるので**予備として 2026-09-17 頃まで維持**。Cloudflare側が1週間安定したら `schedule` ブロックごと削除する（`workflow_dispatch` は手動用に残す）
