# 指示書：GBPクチコミ自動返信システム（承認キュー方式）（2026-06-11）

発行元：PMセッション。実装先：bw5-app開発セッション。
TARO承認済みの構想：**1日4回チェック→新着クチコミをアプリの承認キューへ→スタッフがドラフト編集・承認→システムが自動で返信投稿**。

## アーキテクチャ（確定方針）

```
①Cloudflare Worker（cronトリガー 6:00/12:00/18:00/24:00 JST・無料枠）
   → bw5-appの /api/cron/gbp-reviews を叩く（CRON_SECRETで認証）
②API route: GBP API（公式）で新着クチコミ取得 → Tursoに保存
③未返信の新着があれば Claude API でドラフト生成 → 承認キューに登録
④/staff に「クチコミ返信」承認画面：本文＋編集可能ドラフト＋承認ボタン
⑤承認 → サーバーがGBP APIのreviews.updateReplyで返信投稿 → ステータス更新
```

- **ブラウザ自動化は使わない**。読み取りも投稿もGoogle Business Profile公式API
- Claudeの役割はドラフト生成のみ（Claude API・claude-sonnet系で1件1円未満）
- 承認キュー方式はLSTEP表示名一括更新と同型（既存の運用パターン踏襲）
- Vercel→Cloudflareのフル移行はしない（TARO確認済み）。cronトリガーだけCloudflare Worker（またはGitHub Actions schedule。実装しやすい方でよい）

## 前提・既存リソース

- GCPプロジェクト：GA4 KPI統合で使用中のプロジェクト（boom-drive。ga4-reader SAを作った場所）を流用してよい
- Googleアカウント：boom.sendai@gmail.com（GBPオーナー権限あり）
- 対象ビジネス：「BOOM ストリートダンススクール」（GBP。Maps CID 13939840798292052101 ≠ APIのlocationId。locationIdはAPIで取得すること）
- 現在クチコミ5件・4.6★。返信は全件済み（2026-06-11時点）

## フェーズ1：GBP APIアクセスの確保（最初にやる・ここが律速）

1. GCPコンソールで以下のAPIを有効化：
   - Google My Business API（mybusiness v4。reviews系はここ）
   - My Business Account Management API
   - My Business Business Information API
2. **GBP APIのアクセス申請**（フォーム審査制・承認まで数日〜数週間）：
   - GCP上でAPIを有効化しただけではquota=0。申請フォームから「APIアクセスのリクエスト」を提出する必要がある
   - 申請情報：ビジネス名 BOOM（ダンススクール）、ウェブサイト boom-sendai.com、用途「自店舗のクチコミ確認と返信管理ツール（自社利用・単一ビジネス）」
   - **フォームの最終送信はTAROに画面を見せて確認を取ってから**
3. OAuth設定：
   - **注意：GBP APIはサービスアカウント非対応。OAuth2ユーザー同意フロー必須**
   - OAuthクライアント（Webアプリ型）作成 → boom.sendai@gmail.com で同意 → **refresh tokenを取得してVercel環境変数に保存**
   - スコープ: https://www.googleapis.com/auth/business.manage
4. accountId / locationId をAPIで取得して環境変数に固定

## フェーズ2：データ層（Turso）

```sql
CREATE TABLE gbp_reviews (
  review_id TEXT PRIMARY KEY,        -- GBPのreviewId
  reviewer_name TEXT,
  star_rating INTEGER,
  comment TEXT,
  create_time TEXT,
  update_time TEXT,
  reply_comment TEXT,                -- 投稿済み返信
  reply_time TEXT,
  status TEXT DEFAULT 'new',         -- new / draft_ready / approved / posted / skipped
  draft TEXT,                        -- Claude生成ドラフト（スタッフが編集可）
  drafted_at TEXT,
  posted_at TEXT,
  raw_json TEXT
);
```

## フェーズ3：APIルート

- `GET/POST /api/cron/gbp-reviews`（CRON_SECRET認証）
  - reviews.list で全件取得 → 差分をupsert
  - reply無し＆status=new → Claude APIでドラフト生成 → status=draft_ready
- `POST /api/staff/gbp-reviews/[id]/approve`：編集後ドラフトを受け取り、reviews.updateReply（PUT accounts/{a}/locations/{l}/reviews/{r}/reply）で投稿 → status=posted
- `POST /api/staff/gbp-reviews/[id]/skip`：返信不要としてマーク

## フェーズ4：ドラフト生成（Claude API）

- モデル：claude-sonnet系（最新）。入力：クチコミ本文・星数・投稿者名
- **返信ポリシー（プロンプトに必ず組み込む・クチコミ返信戦略より）**：
  - 公開返信は「入会検討中の見込み客」が読む前提で書く
  - 感謝は具体的に（本文の褒めポイントを引用して言及）
  - 価格への不満：値下げ・値上げのどちらも約束しない。透明性と誠実さで対応
  - ネガティブには真摯に受け止め改善姿勢。言い訳しない
  - 絵文字1〜2個まで、3〜5文程度
- 低評価（★1-2）の場合はドラフトに「※低評価のためスタッフ確認必須」フラグ

## フェーズ5：承認UI（/staff配下）

- 一覧：未対応（draft_ready）を上に。クチコミ本文・星数・投稿日・ドラフト（textarea編集可）
- ボタン：「承認して投稿」「スキップ」
- 投稿結果（成功/失敗）のフィードバック表示
- 既存の/staffハブのデザイン・認可に合わせる（KPIカード同様）

## フェーズ6：cronトリガー

- Cloudflare Worker（無料）に cron trigger "0 21,3,9,15 * * *"（UTC=JST 6/12/18/24時）
  - fetch(`https://<bw5-app>/api/cron/gbp-reviews`, { headers: { 'x-cron-secret': ... } })
- 代替：GitHub Actions schedule でも可（リポジトリにworkflow追加）

## 環境変数

- GOOGLE_OAUTH_CLIENT_ID / GOOGLE_OAUTH_CLIENT_SECRET / GBP_REFRESH_TOKEN
- GBP_ACCOUNT_ID / GBP_LOCATION_ID
- ANTHROPIC_API_KEY
- CRON_SECRET

## つなぎ運用（API承認が下りるまで）

PMセッション側の週次スケジュールタスク（weekly-gbp-review-check・毎週月曜9時）が新着チェック＋ドラフト提示を代行中。API承認が下りてシステムが稼働したら、このタスクは廃止する。

## 制約・注意

- 返信の自動投稿は**必ず人間の承認後**。承認なしの自動投稿は実装しない
- 低評価クチコミは特に慎重に（フラグ表示）
- GBP APIのquota承認が下りない場合はPMセッションに相談（ブラウザ代行のフォールバックあり）
- 質問・GCP/フォーム周りで詰まったらPMセッションへ
