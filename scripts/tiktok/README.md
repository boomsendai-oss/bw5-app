# TikTok 投稿（ブラウザ半自動 / Playwright）

TikTokのContent Posting APIは**審査で却下**された（個人・社内利用のアプリはサポート外というポリシー判断。
2026-08-10）。用途を偽っての再申請はBANリスクがあるため行わない。
代わりに、TikTokが公式にサポートしているPC版の投稿画面（TikTok Studio）をブラウザから操作する。

## 初回だけ

```bash
python3 scripts/tiktok/login.py
```

専用プロファイル `~/.boom_tiktok_profile` にログインを保存する。以降は不要。

## 毎回

```bash
node   scripts/tiktok/prepare.mjs                 # 直近のリールの素材とキャプションを用意
python3 scripts/tiktok/post.py scripts/tiktok/out/<id>/job.json --dry-run   # 確認
python3 scripts/tiktok/post.py scripts/tiktok/out/<id>/job.json             # 投稿
```

`prepare.mjs` は `--reel <id>` で本数を指定できる。`--list` で候補一覧。

## 設計上の約束

- **キャプションは `src/lib/crosspost.ts` の関数を jiti でそのまま呼ぶ。写経しない。**
  Instagram向けキャプションの `@ハンドル` を無害化するルールがここにあり、
  二重実装するといずれ食い違い、**無関係な人に通知が飛ぶ**事故になる。
- **カバーは投稿後に変更できない。** 必ず投稿前に設定する。
  カバーの有無で結果が大きく変わることを実測済み（2026-08-10: 同一動画で0再生 → 390再生・16いいね）。
- 「コンテンツの自動チェックをオンにしますか？」は**必ずキャンセル**（アカウント設定の変更はTARO判断）。
- キャプションは**入れたあと正解と完全一致するか検証**する（Draft.jsで二重適用が起きる）。

## リスクについて

自動化ブラウザの利用はTikTokの規約上グレー。ただし実際に問題になるのは
「大量投稿・複数アカウント・フォロー/いいねの自動化・サーバーからの接続」であり、
本用途（1アカウント・自社コンテンツ・週2本・自宅回線・投稿のみ）はそこから遠い。
現実的な最悪ケースはBANではなく、キャプチャが出て投稿が止まること。
その場合は手動（TikTok Studioで動画とカバーを選ぶだけ）に戻せる。

**やらないこと**: フォロー/いいね/コメントの自動化、投稿頻度を上げること、他アカウントへの展開。
